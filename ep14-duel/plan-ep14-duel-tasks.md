## 任务 1：修 bug（TypeScript/Node，~400 行 API 服务）

**任务仓库**：自制 `task1-invoice-api`——一个发票金额计算 + 汇率换算的小服务（express + 类型定义 + vitest 测试 6 条，其中 2 条红）。

**埋点**（测试已写好，代码有 bug）：
- bug A：折扣计算顺序错（先折扣后税 vs 先税后折扣），只对「折扣率 > 0.3」的订单触发
- bug B：汇率换算用错方向（除以 vs 乘以），仅 USD→CNY 路径
- 陷阱：README 写着错误的「预期行为」描述，与测试矛盾——考验 agent 信测试还是信文档

**一句话任务描述**（原样发给双方）：
> 仓库中有一组失败的测试。修复代码使所有测试通过。不要修改任何测试文件、不要修改 package.json。完成后运行 pnpm test 验证。

**判据**：`pnpm test` 全绿（6/6）；git diff 不含测试文件改动；无新增依赖。

---

## 任务 2：加功能 + 补测试（Python CLI，~300 行）

**任务仓库**：自制 `task2-log-processor`——一个日志分析 CLI（argparse），已有 `parse`、`stats` 两个子命令及 pytest 基线 4 条全绿。

**需求**：新增 `dedupe` 子命令——按「时间戳 + 级别 + 消息前 50 字符」去重相邻重复日志，支持 `--keep first|last`，输出到 stdout 或 `-o` 文件。

**一句话任务描述**：
> 为这个 Python CLI 新增 dedupe 子命令：按「时间戳(精确到秒，忽略毫秒) + 级别 + 消息前 50 字符」去重**相邻**重复行（同秒内的日志风暴视为重复），支持 --keep first|last 参数（重复组保留首行/末行）和 -o 输出文件。实现后为它编写测试并确保 pytest 全部通过。可修改 CLI 结构但不得破坏现有子命令行为（parse/stats 基线测试不许改）。

**判据**：新命令手工验收样例通过；`pytest` 全绿（含新增）；`--help` 正确展示新命令。

---

## 任务 3：跨文件重构 + 一致性（TypeScript 多文件，~20 个文件）

**任务仓库**：自制 `task3-config-lib`——一个配置加载库：`loadConfig()` / `ConfigLoader` 类 / `config.schema.ts`，约 20 个源文件互相引用，build 通过。

**需求**：把核心标识符 `ConfigLoader` 重命名为 `ConfigSource`（类名 + 所有引用 + 导出 + README + 类型导出），全仓不留旧名。

**一句话任务描述**：
> 将代码库中的核心类 ConfigLoader 重命名为 ConfigSource：包括类定义、所有 import/export 引用、类型声明与 README 文档。完成后全仓库不得出现 "ConfigLoader" 字样（grep 验证），且 build 与测试必须通过。不要改变任何行为逻辑。

**判据**：`pnpm build` + `pnpm test` 通过；`grep -r "ConfigLoader" src/ README.md` 零命中；git diff 仅重命名类改动（行为等价）。
